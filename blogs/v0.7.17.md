# JishuShell更新日志 | v0.7.17

---

JishuShell v0.7.17 正式发布。本次更新的主线，是继续把 **OpenClaw 与内置服务之间的连接链路做短、做稳**：内置文件空间 **Drive** 现在通过 OpenClaw 原生 MCP 直接提供工具，知识库也彻底移除旧的适配路径并跟进最新工具契约；同时，JishuShell KB 的网页、HTTP 与 WebSocket 代理补齐了服务端鉴权，既避免密钥暴露到浏览器，又让已安装实例可以自动修复。除此之外，我们还恢复了 OpenClaw 控制面板内的一键自更新，在 Nomad 托管环境中也能正确完成升级与重启。

---

## 重点更新：Drive 接入 OpenClaw 原生 MCP

### Agent 使用文件更直接

内置文件空间 **Drive** 不再依赖额外的 `mcporter` 中转，而是注册为 OpenClaw 原生 MCP 服务。Agent 可以直接调用文件工具完成浏览、读取、搜索、写入、移动、删除、查看空间占用，以及把文件解析为可发送的本地路径。

对用户来说，使用方式不变：仍然可以直接说「帮我找一下上周的会议纪要」「把这份报告保存到文档目录」「把刚生成的 PDF 发给我」。变化发生在底层——工具发现与调用路径更短，少了一层命令行转发，文件操作和跨渠道发文件更加稳定。

升级后，JishuShell 会保留用户自己配置的 MCP 服务，只迁移由系统管理的 Drive 配置，并自动清理旧的中转配置，避免同一套工具重复出现。

---

## 重点更新：知识库链路收敛，访问更稳更安全

### 彻底切换到 JishuShell KB 原生 MCP

OpenClaw 的知识库连接现在统一以 **JishuShell KB 原生远程 MCP** 为准，并跟进新版 `jishu-kb` profile 与 `jishukb-mcp-v1` 工具契约。此前已经被原生 MCP 取代的本地 stdio shim 代码正式移除，升级时仍会清理旧实例留下的 shim 文件，避免残留配置干扰工具加载。

旧的 AnythingLLM 知识提供路径也已退出 OpenClaw：它不会再出现在可选的知识库候选中，已有的旧绑定会在读取和修复时自动清理，防止 OpenClaw 继续连到已经不受支持的知识提供方。

### JishuShell KB 代理鉴权补齐

JishuShell KB 的 Web UI、HTTP API 与 WebSocket 访问现在都由 Core 在服务端解析实例凭据并注入鉴权头。访问令牌不会下发到浏览器可见的元数据中，既减少了凭据泄露风险，也解决了知识库开启鉴权后，通过面板嵌入页面或 capability proxy 访问可能失败的问题。

这套修复同时覆盖新安装与存量实例：新安装的 JishuShell KB 会直接带上正确的鉴权声明；已有实例会在 `repair` / 运行时修复过程中自动补齐 spec 与 manifest，无需手工重装知识库。

JishuShell KB 的内置镜像也切换为 `latest`，后续安装与重建会跟随当前知识库版本。

## 重点更新：恢复 OpenClaw 控制面板内一键自更新

在 JishuShell 的 Nomad 托管环境里，OpenClaw 自带的更新动作此前无法像 systemd 安装那样自行重启服务，可能出现包已更新、界面却提示失败，或重启后才发现实际已经升级的情况。

v0.7.17 为控制面板补上了专用更新桥接：当你在 OpenClaw 页面里触发更新时，JishuShell Core 会接管升级任务，在实例内部运行 OpenClaw 自带的 updater，返回真实更新结果，再由 Nomad 重启并验证实例。更新期间可以看到任务进度，重复点击会复用同一个运行中的任务，失败时也会返回明确原因。

针对控制面板客户端延迟创建、WebSocket 在重启时提前断开的情况，本次也补了兼容处理：更新请求会在 WebSocket 边界被稳定接管，真实 updater 结果先返回给页面，再执行实例重启，避免「升级成功却显示失败」。

---

## 更多改进

- **配置迁移更干净**：Drive 与知识库升级为原生 MCP 后，只清理 JishuShell 管理的旧配置和残留文件，不影响用户自定义 MCP 服务。
- **知识库契约更一致**：统一使用导出的 profile、工具契约版本与工具清单常量，减少服务端升级后因名称漂移导致的工具发现失败。
- **存量实例可自愈**：运行时修复会补齐 JishuShell KB 的 provider auth 声明并同步 manifest 摘要，无需删除数据或重建实例。
- **凭据边界更清晰**：Capability 代理从实例环境或集成配置中按需解析令牌，并在服务端覆盖请求鉴权头；浏览器只看到代理地址，不接触真实 token。
- **更新流程更可靠**：OpenClaw 更新任务会校验实例状态和托管目录、限制超时时间，并在完成后统一交给 JishuShell 生命周期管理重启。

**升级方式：**

```bash
npm install -g jishushell@0.7.17
```

或通过 Dashboard 顶部的版本更新横幅一键升级。

如果你是**系统级安装**（已注册 systemd / launchd 服务），`npm install` 只会刷新包文件与 CLI / 面板启动脚本，并不会重启服务、迁移实例。这一步完成后，命令行会用醒目的 `ACTION REQUIRED` 提示你「本地修复尚未执行」，并给出收尾命令——照着复制执行即可。

按提示执行 `sudo jishushell repair`（若 sudo 找不到命令，用提示里的绝对路径 `sudo ~/.jishushell/bin/jishushell repair`）即可完成收尾。`repair` 会自检本地状态、修复存量 JishuShell KB 的鉴权声明，并统一对账和重载系统组件。完成后刷新已打开的 JishuShell 浏览器标签页，即可加载更新后的界面。

> 普通的 `npm install -g jishushell`（非系统级服务安装）不会出现这一步，包文件刷新后即可直接使用。
